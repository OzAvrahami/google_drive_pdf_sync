Panda 2.0 — UX model & two visual directions
Grounded in the eight current-state docs. The app is a Hebrew-first, RTL desktop work queue: documents enter from Google Drive, get parsed, and flow through review → approval → Excel export. Below is the proposed model; the two windows show the same real screen (Needs Attention) in two aesthetics — pick 1A or 1B and I build the full set.
A · Information architecture
One work queue, six locations in the right rail. Every location is a filtered view of the same document store, not a separate screen:
Overview — what needs me now, and today's throughput.
Inbox — discovered / re-queued, not yet processed (status new).
Needs Attention — everything that can't auto-clear.
Ready — processed & approved, awaiting export.
Irrelevant — user-confirmed exclusions.
History — exported records.
B · A day in Panda
1. Scan Drive (background task, non-blocking) → new docs land in Inbox.
2. Process → high-confidence (≥0.75) auto-advance to Ready; the rest route to Needs Attention with a reason.
3. Work the attention queue in the Document Workspace — source + fields side by side, keyboard next/prev, no modal.
4. Correct, approve (single or batch), resolve duplicates in-context.
5. Export approved → Excel; records move to History.
C · Biggest changes vs today
• Modal review → embedded Document Workspace with source preview (no external PDF app).
• Blocking progress dialog → non-blocking task dock.
• No batch approve → multi-select batch actions.
• No duplicate comparison → side-by-side resolve.
• Raw status dropdown → guided actions; numbers sort numerically, not as text.
